# gitignore baseline

An annotated baseline, grouped by concern. Each group states *why* it's
ignored so an adopting repo can prune groups that don't apply rather than
copying every line blindly — a repo with no compiled-language packages
doesn't need that group's lines just because this file lists them.

## Worktree-local root

```
.local/
```

`.local/` is the single git-ignored per-worktree root for all ephemeral state
and scratch, shared by humans and every agent vendor:

```
.local/
├── tmp/        # scratch (instead of /tmp or ad-hoc tmp/)
├── logs/       # service + stack logs
├── pids/
├── <stack>/    # per-stack state and instances
└── env files   # worktree-derived env, ports
```

Ignore it unconditionally, even before any local stack exists — it is the
one destination every future stack, script, and agent vendor is expected to
write scratch into instead of inventing its own tracked or ad-hoc temp
location. Full ownership and layout: `cmk:local-stack`.

## Dependency directories

```
node_modules/
vendor/
.venv/
venv/
```

Package-manager output is reproducible from the lockfile/manifest and is
often too large or platform-specific to track. Keep only the lockfile itself
tracked; the resolved tree is regenerated by `install`.

## Build outputs (per ecosystem in use)

```
dist/
build/
target/
*.egg-info/
__pycache__/
*.pyc
```

Build artifacts are regenerated from source on every build and differ by
machine/toolchain version; tracking them causes noisy diffs and stale-binary
bugs. Include only the lines for ecosystems the repo actually has — an
all-ecosystem copy-paste ignores nothing extra, but it does invite confusion
about which lines are load-bearing here.

## Env-file policy

```
.env
.env.*
!.env.example
```

Real env files carry secrets or machine-specific values and must never be
committed. The negated `!.env.example` line keeps a checked-in template
tracked so the ignore pattern above it doesn't also swallow the example
contributors are meant to copy from.

## Editor / OS noise

```
.DS_Store
Thumbs.db
.vscode/
.idea/
*.swp
*.swo
*~
```

Per-machine editor state and OS bookkeeping files carry no project meaning
and differ per contributor; tracking them produces churn with no signal.

## AI working artifacts

```
.superpowers/
.raki/
docs/superpowers/
docs/plans/
```

Spec, plan, and session-state scratch that AI agent workflows generate is
disposable working memory, not a documented deliverable — anything from it
worth keeping gets distilled into tracked docs by hand. Ignore the whole
directory rather than picking through its contents, and extend this group
with any other vendor-specific scratch directory a given agent tool adds.

## Logs and local databases

```
*.log
*.db
*.sqlite
*.sqlite3
```

Runtime output and local database files are regenerated by running the
system and are usually large or binary; they belong in `.local/logs/` (see
above) rather than at arbitrary tracked paths, but the blanket pattern here
catches ones a tool writes elsewhere by default.
