# Skill conventions

## What

Every skill under [`skills/`](../../../skills/) is one flat package, `skills/<name>/`, named
`cmk:<name>`. The kit takes its behavior from the Engineer Pack and its shape from this repo
([ADR 0001](../../decisions/0001-jdk-engine-cmk-shape.md)). The house rules are in
[`CONTRIBUTING.md`](../../../CONTRIBUTING.md) and enforced by `scripts/skill-lint.sh`; this page
says where each convention lives so an agent can check one without reading the lot.

## Approach

**Package.** `SKILL.md`, optional `TESTS.md` and `eval.json`, and the folders `references/`,
`scripts/` and `agents/` — nothing else at the root. Detail lives in `references/` (nested
folders such as `references/templates/` are fine), reached by a pointer whose wording says when
to load it. A script sits in `scripts/`, is executable when it is an entry point, and is named
as `scripts/<file>` by the skill; a library module is imported by a sibling. No path climbs out
of the package; another skill is cited as `cmk:<name>` and its shared file as
`` `cmk:<name>`'s `references/<file>` ``.

**Frontmatter.** `name`, `description` on one physical line, `version` (semver per skill), and
`disable-model-invocation: true` only on user-invoked skills. A model-invoked description opens
"Use when…", carries the words a user types and the outcome noun, never the step list; routing
is measured (`TESTS.md` § Description routing) because a rename alone moved several skills from
5/5 to 0/5. A user-invoked description is one plain line naming the deliverable.

**Hand-offs.** `REQUIRED SUB-SKILL: use \`cmk:<x>\`` names only model-invoked skills; a
user-invoked one is named for the person to run (`/cmk:go`). A core skill reaches a pack skill
only when it is installed (`skills/agent-vendors/references/packs.md`).

**Size.** 150 lines is the target. A longer `SKILL.md` has an entry in
`scripts/skill-size-budget.json` equal to its length; the entry only goes down.

**Evidence.** `TESTS.md` records each behavior's RED (the failure without the text) and GREEN,
scored from artifacts, never from the agent's report; `eval.json` holds the runnable
assertions (`eval_id`, `eval_name`, `prompt`, `assertions`, and `kind` / `derived_from` where
set). Text with no recorded failure behind it is not added.

**Families** (the explorer's categories, `lib/skill-types.ts`): documentation (specs,
requirements, design, decisions, glossary, catalog), delivery (the closed workflow, its five
commands and the build–review–ship chain), setup and infra facets, testing and code, session
companions, and the opt-in packs — roadmap, acceptance and UI, ops, quality, project,
maintainers, extras.

**Shapes.** Setup facets end in a report-only `## Verify`. Delivery skills are gates inside the
closed workflow owned by `cmk:delivery-workflow` — they move a ticket only through the states
in its `references/closed-workflow.md`. Docs skills write the triad under `docs/specs/` and the
standing docs under `docs/requirements/`, `docs/design/` and `docs/decisions/`.

## Where

- Lint: `scripts/skill-lint.sh` (bash checks) and `scripts/skill_checks.py` (ratchet,
  descriptions, evals, hand-offs, packs, scripts, paths, package root).
- Port from the Engineer Pack: `scripts/port-jdk.py`, `scripts/port-map.json`.
- Per-family maps: the other pages in this folder, generated by `scripts/gen-ai-skill-maps.py`.
- Packs: `skills/agent-vendors/references/packs.md`.
- The workflow: `skills/delivery-workflow/references/closed-workflow.md` and
  `references/scope-band.md`.
